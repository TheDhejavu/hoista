---
title: "Install Hoista"
description: "Install the CLI, the daemon and Desktop."
---

Hoista has two core programs. `hoist` is the CLI and `hoistd` is the daemon. Desktop is an optional app that uses the same daemon. Pick your system:

<CodeGroup>
```bash macOS and Linux
curl -fsSL https://hoista.dev/install.sh | sh -s -- v0.1.0-beta.3
```

```powershell Windows
.\install.ps1 -Version v0.1.0-beta.3
```

```bash From source
git clone https://github.com/TheDhejavu/hoista.git
cd hoista
cargo install --locked --path bin/hoist
cargo install --locked --path bin/hoistd
```
</CodeGroup>

The version is required. Both scripts need [cosign](https://docs.sigstore.dev/cosign/system_config/installation/) 3: they check the release's signature with it and stop if it's missing or the check fails.

## macOS and Linux

The script works on macOS (Apple Silicon or Intel) and Linux (x86_64). It installs `hoist` and `hoistd` into `~/.local/bin`, then runs `hoist service install` so Hoista starts at login. Add that folder to your `PATH` if it isn't there. It takes two more arguments, in this order:

| Argument | Use |
| --- | --- |
| `[destination]` | Install into this folder instead of `~/.local/bin` |
| `--start-at-login` or `--no-service` | Start Hoista at login (the default), or install the binaries only |

To skip login startup, give the folder too:

```bash
curl -fsSL https://hoista.dev/install.sh | sh -s -- v0.1.0-beta.3 "$HOME/.local/bin" --no-service
```

Without the login service, `hoist` still starts the daemon when a command needs it.

## Windows

On Windows (x86_64), run `scripts/install/install.ps1` from the repository. It installs `hoist.exe` and `hoistd.exe` into `%LOCALAPPDATA%\Hoista\bin`. Add `-Destination PATH` to choose another folder, and `-NoService` to skip login startup.

There is no Desktop app for Windows; the CLI and daemon are all you need.

## From source

You need [Rust](https://rustup.rs); rustup installs the version pinned in `rust-toolchain.toml`. `cargo install` builds `hoist` and `hoistd` in release mode and puts both in `~/.cargo/bin`. Keep them in the same folder: the CLI starts the daemon from there. Run `hoist service install` after they're in place to start Hoista at login. The login service records their path, so moving them later breaks it.

To build Desktop from source, you also need Node.js 22 or later. On Linux, install the system webview's libraries first: `libwebkit2gtk-4.1-dev`, `libayatana-appindicator3-dev` and `librsvg2-dev` on Debian and Ubuntu.

```bash
npm ci
npm run desktop:build
```

The app is in `apps/desktop/src-tauri/target/release/bundle/`. On Linux, ask for a package with `npm run desktop:build -- --bundles deb,appimage`.

## Desktop app

On macOS, add `--desktop` to the install command. It checks the release signature, then puts `Hoista.app` in `/Applications` (or `~/Applications` if that isn't writable):

```bash
curl -fsSL https://hoista.dev/install.sh | sh -s -- v0.1.0-beta.3 "$HOME/.local/bin" --start-at-login --desktop
```

Hoista isn't signed with an Apple Developer ID yet. A `.dmg` downloaded in a browser gets macOS's "unidentified developer" warning, and the script avoids it because files fetched with `curl` aren't flagged by the browser. If you do download the `.dmg` yourself, run this once after dragging the app to Applications:

```bash
xattr -dr com.apple.quarantine /Applications/Hoista.app
```

On Linux, download the package from [GitHub releases](https://github.com/TheDhejavu/hoista/releases). Use only the files listed on the release page.

| System | Package |
| --- | --- |
| macOS | Apple Silicon and Intel |
| Linux | AppImage and Debian package |

Desktop uses the same daemon as the CLI, so install the CLI and daemon too.

## Upgrade

Run the install command again with the new version. The installer replaces `hoist` and `hoistd`, and stops the engine from the old version so the new one starts in its place. Your projects, accounts and settings stay where they are.

If you installed an earlier beta with an older copy of the script and Desktop shows "Try again", the old engine is still running. Run `hoist service restart`, or quit and open Desktop again.

## Check it works

```bash
hoist --version
hoist doctor
```

`hoist doctor` checks that everything is installed and working.

To run Hoista in your own cloud account instead, see [your remote](/guides/remote).
