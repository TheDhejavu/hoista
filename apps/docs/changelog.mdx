<Update label="0.1.0 Beta 4" description="v0.1.0-beta.4 · 22 November 2026" tags={["Beta"]}>
**Added**

- Windows: the CLI and daemon are in the release again, and `install.ps1` installs them. hoista.dev shows the PowerShell command on Windows.
- Hoista Desktop for Windows, as an `x64-setup.exe` installer.
- Linux on Arm64: the CLI and daemon (`install.sh` picks them on its own), and Desktop as an AppImage and a `.deb`.
- Hoista runs on a computer without a keychain, such as a Linux server or WSL: put a key in `~/.config/hoista/sealed-key` and tokens are kept in a sealed file in `~/.hoista`. Before, `hoistd` didn't start there at all.
- Hetzner Cloud: connect a project to see its servers and volumes, each server's CPU, disk and network, turn servers off and on, delete servers and volumes, and run Hetzner's own operations from the **Hetzner** tab.
- Make a Hetzner server from a project (**Add server**, or `add_to_project` with kind `server`): Ubuntu 24.04 with Docker, a firewall that lets in only SSH, HTTP and HTTPS, security updates, and an SSH key that only Hoista holds.
- A server Hoista made shows as deploying until it has set itself up, and as failing if that failed. **Add server** can attach a volume and turn on Hetzner's backups, and follows the server until it's ready. A server's Settings tab lists everything done on it.
- Agents can work on servers Hoista made through new MCP tools: `server_status`, `server_logs`, `server_read_file`, `server_run`, `server_write_file` and `server_deploy_key`. Commands and files ask you first; with Full access they stop asking only once you allow it for that server, and steps that can lock you out always ask.

**Fixed**

- The Windows install script asked for a download that no release had, so it always failed.
- Desktop didn't find the CLI where `install.ps1` puts it on Windows.

**Known limitations**

- Hoista Desktop is not yet signed with an Apple Developer ID or notarized, so macOS asks you to confirm the first open. The Windows installer isn't signed either, so SmartScreen asks too.
- On Windows, local builds can't run isolated, so Hoista stops them unless you allow them in **Settings → Safety**.
- There are no builds for Windows on Arm.
- Providers connect with API tokens only; one-click sign-in with a provider is turned off for now.
- The beta update channel in Desktop's settings is not available yet. To move to a newer beta, install it from its release page.

[v0.1.0-beta.4 on GitHub](https://github.com/TheDhejavu/hoista/releases/tag/v0.1.0-beta.4)
</Update>

<Update label="0.1.0 Beta 3" description="v0.1.0-beta.3 · 13 November 2026" tags={["Beta"]}>
**Fixed**

- Hoista Desktop for Mac was not sealed with a signature, so a copy downloaded in a browser opened as "damaged and can't be opened", with no way past it. It is now sealed, and macOS shows its normal "can't verify" prompt, which **Open Anyway** in System Settings clears.
- Installing a release over an older one failed while the older engine was still running: the installer reported that the engine and CLI versions differ, and Desktop showed "Try again" on every screen. The installer now stops the previous engine, and the new one starts at login or on the next `hoist` command.

**Added**

- On a Mac, `install.sh --desktop` also installs Desktop into `/Applications`, after checking its signature. It opens without a warning because the file never passes through a browser. hoista.dev shows this command on Macs.

**Known limitations**

- Hoista Desktop is not yet signed with an Apple Developer ID or notarized, so macOS asks you to confirm the first open.
- No Windows builds yet, of Desktop or the CLI.
- Providers connect with API tokens only; one-click sign-in with a provider is turned off for now.
- The beta update channel in Desktop's settings is not available yet. To move to a newer beta, install it from its release page.

[v0.1.0-beta.3 on GitHub](https://github.com/TheDhejavu/hoista/releases/tag/v0.1.0-beta.3)
</Update>

<Update label="0.1.0 Beta 1" description="v0.1.0-beta.1 · 13 November 2026" tags={["Beta"]}>
The first public beta of Hoista: the open-source control plane for your infrastructure, built for AI agents.

**Added**

- `hoistd`, the engine, and `hoist`, the CLI. The CLI starts the engine when a command needs it, and `hoist service install` starts it at login.
- Hoista Desktop for macOS (Apple Silicon and Intel) and Linux (AppImage and Debian package).
- Providers: Cloudflare, Fly.io, Railway, Vercel, Neon, Supabase, Render, Resend, Runpod, Modal and GitHub. Each is connected with an API token.
- Import of what already runs on your providers, grouped into projects.
- Deploys from a folder, with a plan you see first, live progress and rollback to any earlier deploy.
- Logs, metrics and daily usage as each provider reports them.
- Variables (hidden, or from a `.env` file), custom domains with DNS checks, and environments such as production and staging.
- Billing: what each provider has billed this period, and plan limits. Hoista never estimates cost.
- An MCP server for coding agents and chat apps, over stdio (`hoist mcp`) or HTTP on `127.0.0.1:8788`, with per-agent access (View only, Ask for approval, Full access) and a record of every call.
- Skills for agents, installed with `hoist skills install`.
- Remotes: run Hoista on Railway, Fly.io or Docker so agents can reach it while your computer is off, and move this computer's projects there in one step.
- Backups of Hoista's own state, an encrypted export for moving to another computer, and webhooks.
- Signed releases: every archive is signed with Sigstore from this repository's release workflow, and the installers refuse anything that doesn't verify.

**Known limitations**

- This is a beta. Expect rough edges, and please [report them](https://github.com/TheDhejavu/hoista/issues).
- Hoista Desktop is not yet signed with an Apple Developer ID or notarized. macOS blocks it on first open; see [Install](/getting-started/install#desktop-app) for how to open it.
- There is no Desktop app for Windows yet. The CLI and engine run on Windows.
- Providers connect with API tokens only; one-click sign-in with a provider is turned off for now.
- The beta update channel in Desktop's settings is not available yet. To move to a newer beta, install it from its release page.

[v0.1.0-beta.1 on GitHub](https://github.com/TheDhejavu/hoista/releases/tag/v0.1.0-beta.1)
</Update>
