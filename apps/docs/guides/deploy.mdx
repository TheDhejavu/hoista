A deployment starts with a plan built from the project's source. The plan lists the resources, provider accounts, regions and environment variables before Hoista changes anything. [Connect](/guides/accounts) the target account first.

## From Desktop

Desktop has no deploy form. Ask a [connected agent](/agents/connect) to deploy, for example "Deploy this project with Hoista", or use the CLI below. **Deploys** in the sidebar shows every deploy as it runs, and a project's **Deploys** tab shows that project's history.

For a watched project, the provider still runs the build. Use **Deploy newest commit**, or a row's menu to redeploy, restart or roll back. Hoista asks the provider to do it.

## Create and review a plan

```bash
hoist plan ./my-app --project my-app
hoist plan show PLAN_ID
```

Check the detected framework, resource names, accounts, regions, required variables and any database migration step. To change where a resource goes:

```bash
hoist plan set PLAN_ID RESOURCE_NAME --account ACCOUNT
hoist plan set PLAN_ID RESOURCE_NAME --region REGION
```

`--region -` clears the region. To change more, pipe edited JSON from `hoist plan show PLAN_ID --json` into `hoist plan edit PLAN_ID`.

If the source changes, create a new plan. Set required values through [variables](/guides/environment).

## Deploy

Deploy a folder in one step:

```bash
hoist deploy ./my-app --project my-app -m "First deploy"
```

The CLI follows the deploy step by step until it is live or fails. `--detach` starts it and returns straight away. `-m` saves a note with the deploy.

Or deploy a reviewed plan:

```bash
hoist deploy --project my-app --plan PLAN_ID --plan-revision REVISION --request-key REQUEST_UUID
```

Keep the same request key if you retry the same deployment. Hoista rejects the key if the content changed. `hoist deploys request REQUEST_UUID` finds the deploy a key started.

## Follow, cancel and roll back

```bash
hoist status my-app
hoist deploys my-app
hoist deploys show DEPLOY_ID --log
hoist logs my-app --follow
hoist cancel DEPLOY_ID
hoist rollback DEPLOY_ID
```

In a terminal, `hoist rollback` without a deploy ID lets you pick one from the project's deploys.

A successful build does not prove the app works. Check the running project as well.

Cancelling asks the provider to stop, and the provider may already be past that point. Rolling back switches which version serves traffic. It does not undo database migrations.

If a request times out, check what happened before you retry. See [operation outcomes](/guides/backups).
